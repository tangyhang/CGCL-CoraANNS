# 补充材料与发布

项目仓库：[CGCL-CoraANNS](https://github.com/tangyhang/CGCL-CoraANNS)。

## 补充材料提交要求

1. 提交补充材料时，必须提供指向材料的 URL。
2. 使用标准、公开可访问、隐私政策清晰且有长期保存保障的平台，例如公开 GitHub 仓库。
3. 个人主页不被接受。
4. 链接的安全性或匿名访问方式若存在疑虑，会延误论文评审与接收。
5. 如果不提交用于复现的材料，必须解释合理原因，例如版权限制、商业化考虑或确实不适用。
6. “没时间”或“整理代码工作太多”不是有效理由；接收前仍需要解决可用性问题。
7. EA&B 类论文必须提交补充材料，没有上述豁免。

## 复现材料

- 明确的目录职责，区分系统实现、入口、依赖、实验、数据工具与测试。
- 从干净目录可执行的构建命令，以及依赖、硬件和版本说明。
- 小数据端到端示例，降低验证环境的成本。
- 记录数据格式、索引训练/构建步骤、参数来源和实验运行命令。
- 保存原始日志、recall 评估模式和结果元数据。
- 保留原许可证、上游归属和第三方声明。
- 数据集、构建产物和实验结果分别放在 `data/`、`build*/` 和 `results/`。

## 发布内容

- 公开仓库 URL 和论文对应的 tag/release。
- 论文作者、标题和引用信息。
- 数据集的精确子集、准备方法和获取地址。
- 实验硬件、依赖环境、索引配置和原始结果。
- 长期归档地址或归档标识。
